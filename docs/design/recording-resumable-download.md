# CLI 录音断点续传与 OSS SDK 复用方案

状态：已实现，分支 `feat/0.12.0-recording-resume`；真实 RECORDING 任务签名刷新待服务端联调。  
代码基线：`origin/release/0.12.0`，`1569600`。  
日期：2026-09-29。

## 1. 结论

复用 CLI 已接入的阿里云 OSS Go SDK v2 及签名 URL 适配层，将迁移下载中的通用能力抽出后供录音使用。不复制 OpenClaw 插件的 TypeScript 下载器，也不直接让录音调用迁移业务的 `Download(taskId, path)`。

第一阶段提供单次后台下载流程内的断点续传、有限重试和签名刷新。进程退出后恢复已完成分片不在本阶段范围；重启仍由现有录音恢复流程重新发起下载。

不改变 App 的录音同步协议形态：`recordings.result.write` 异步受理，使用原 `recording.status` 事件及 `recordings.status` 查询确认完成，不新增事件名或 HTTP 录音入口。

## 2. 已有实现与缺口

| 位置 | 已有能力 | 本次处理 |
| --- | --- | --- |
| `internal/recording/downloader.go` | 每次 5 分钟、最多 3 次尝试；临时文件落盘；本机代理连接被拒绝时降级直连 | 当前失败会删除片段、从头重下；接入共用下载器并保留代理兼容 |
| `internal/recording/result_writer.go` | 异步下载、每条录音下载锁、旧结果丢弃、完成通知 | 保留业务语义，注入可选刷新回调 |
| `internal/transfercloud/transport.go` | SDK v2 下载器、8 MiB 分片、并发 3、checkpoint、签名 GET 适配、范围与 ETag 校验 | 抽出通用下载能力，迁移和录音分别提供业务参数 |
| `internal/transfercloud/client.go` | 获取 `/api/device/file/plugin/download-url`，使用 CLI API Key | 抽出或扩展可复用的签名获取能力，避免把迁移规则带入录音 |
| `internal/transfercloud/transport_test.go` | 中途断流恢复、文件一致性、错误范围/版本和重定向测试 | 保留并补录音接入测试 |

现有适配器用 `GET Range: bytes=0-0` 获取元数据，避免把 GET 签名错误用于 HEAD。后续分段请求使用 `Range` 和 `If-Match`，要求 206、正确 Content-Range/长度及一致 ETag。SDK 管理并发分片、续传和 checkpoint。

现有迁移 checkpoint 位于临时目录，调用结束即清理。因此“使用 checkpoint”不代表支持跨进程续传。录音尚未接入 `ossTaskId`，目前 403 直接失败。

## 3. 模块拆分

建议新建内部通用包 `internal/ossdownload`（名称可在实现时调整）。依赖方向：

```text
recording ───────┐
                ├── ossdownload ── OSS SDK v2
transfercloud ──┘
```

通用包负责：

- 签名 GET URL 与 SDK 接口适配，Range/ETag/长度校验。
- checkpoint 生命周期、分片并发、下载重试及取消。
- 通过调用方提供的 HTTP client 发送请求，通过可选回调获取新 URL。
- 将完整文件交给调用方；不更改录音状态、不删除 OSS 对象、不读取业务账号凭据。
- 结构化错误及脱敏诊断，日志不输出签名参数、API Key 或 STS 凭据。

调用方负责：

- 录音：本地复用判断、当前下载轮次、目标路径、文件大小限制、成功提交及事件。
- 迁移：任务 ID 校验、迁移包 5 GiB 上限、签名获取和导入流程。
- API Key 只发送给业务服务，绝不附加到 OSS 请求。

不要直接复用迁移 `Download` 的全部封装：它强依赖 taskId、迁移命名/错误码、5 GiB 限制和目标文件 `O_EXCL` 创建策略，不适合所有旧录音请求。

## 4. 新旧 App 字段兼容

新版请求在顶层可增加：

```json
{
  "recordingId": "app-recording-id",
  "ossUrl": "https://bucket.oss-cn-hangzhou.aliyuncs.com/audio.ogg?...",
  "ossTaskId": "upload-service-task-id",
  "createdAt": "2026-09-29T14:30:00+08:00",
  "transcript": { "text": "转写正文" }
}
```

- `ossTaskId` 可选，表示上传服务任务，仅用于刷新链接及可选回显。不是 `transcript.source.taskId`，不使用 OSS Multipart uploadId。
- 旧 App 只有 URL 时仍能下载和续传；缺少 taskId 时不能调用刷新服务，403 按失败处理。
- 提供 taskId 时要求非空字符串、最多 256 字符，并同时提供音频 URL；不沿用迁移业务的固定 ID 格式校验。
- 保存到录音索引；写入响应、列表、详情/状态查询及事件在有值时回传，无值时省略。
- 沿用插件契约：收到不含 taskId 的新 URL 写入时清除旧 taskId，避免用旧任务刷新新地址；不含音频 URL 的仅结果更新保留现有音频关联。
- 保留现有按 recordingId/本地非空音频复用及 URL 轮次判断；taskId 不参与音频去重。
- `createdAt` 使用 App 原始录音时间，现有采集时间处理逻辑不改；不使用转写生成时间或同步时间替代。

## 5. 下载流程

1. 接收结果并落盘转写/总结，返回受理状态。
2. 复用已有可用音频；需要下载时，在现有录音锁内启动本轮任务。
3. 以 Range 探测源站。支持分段且可校验版本时，使用 SDK 下载；复用本轮 checkpoint。
4. 网络中断后由 SDK/外层策略有限重试；不要把两层重试次数相乘成失控的总请求数。
5. 链接失效时执行第 6 节刷新策略；保持同一下载目标和 checkpoint 身份，不用完整签名 URL 作为唯一身份。
6. 全量完成并校验后，通过现有 `CommitResultAudioDownloaded` 提交；只接受仍属于当前 URL 轮次的结果。
7. 发出原来的 `recording.status`，最终状态必须是 `downloaded` 且有 `audioFile`。失败保留转写结果，通过原状态/查询返回错误。

刷新后的签名 URL 是本轮下载的传输地址，不直接作为新的录音交付轮次。提交时仍核对原始交付 URL，避免与现有旧结果丢弃逻辑冲突。

若新链接的 ETag 或总长度变化，SDK 的 checkpoint 元数据校验不通过，从头下载；稳定版本可复用已完成分片。测试覆盖签名刷新前后版本保持与 ETag 变化两种情况，最终内容逐字节校验，不拼接不同版本。

## 6. 签名刷新与超时策略

首期与已发布测试的插件行为对齐：每次后台下载流程最多刷新一次链接；重新发起下载可重新计数。这是保护性限制，不是上传服务约束。长时间下载若再次过期仍可能失败；后续可单独调整为有限多次刷新，不在复用 SDK 时悄然改变协议行为。

- 仅在明确 HTTP 403 且有 taskId 时请求刷新；401/404、签名服务拒绝、未知任务等不无限刷新。
- 刷新使用 CLI 当前账号的 API Key 和所选环境；开始下载时记录凭据/环境，刷新前校验未改变，避免切换账号后继续旧任务。
- 响应校验服务成功码、匹配 taskId、有效 signedUrl 和未来 expiresAt；时间戳兼容服务端 Long 十进制字符串。
- 刷新 URL 需满足 HTTPS 和允许的 OSS 公网域名规则；沿用现有安全策略，不增加会误伤 VPN Fake-IP 的 DNS/IP 分类检查。
- 刷新前后检查任务是否已被新交付替代；过期回调不得改写当前状态。

录音下载预算：每个请求响应头 20 秒、每个响应体连续无数据 30 秒、单次尝试 30 分钟、整轮最多 60 分钟、默认 8 次外层尝试，退避封顶 30 秒。最后一次尝试遇到可刷新的 403 时，额外允许一次刷新后的下载（仍受整轮预算限制）。SDK 会从断流偏移继续请求；适配层限制同一 Range 每次尝试最多请求 3 次，避免零进展重试空转。每个并发分片单独计算停滞时间。

现有迁移 client 的 5 分钟整请求 Timeout 不应原封不动套用到录音长下载。迁移原有参数先保留，通过调用方选项分别配置。

## 7. 旧地址、代理与磁盘兼容

- 服务器忽略 Range 返回 200：转为有长度/大小限制的单流下载，清除不兼容片段；不得把完整响应追加到旧片段后面。
- 缺少可靠 ETag：允许旧录音以单流下载，这种源站无法保证续传能力；Content-Range、长度或版本校验错误则拒绝，不能静默接受错误片段。
- 保留现有本机代理 `ECONNREFUSED` 时降级直连；不得对远端授权错误或任意网络失败无条件绕过代理。
- SDK Range 请求和单流回退都使用统一 transport 策略；旧普通 URL 的兼容策略与刷新后私有 OSS URL 的重定向限制分开处理。
- 临时文件置于录音目标所在文件系统，权限 0600；完整下载且当前轮次有效后再提交，防止半文件被当作可复用音频。
- 不改变用户已有音频的复用规则，不让迁移功能的抽取回归上传或导入行为。

## 8. 验收

| 场景 | 预期 |
| --- | --- |
| 旧 App 无 taskId | 正常写入、下载、状态通知；响应不强制新增字段 |
| 下载途中断流 | 后续请求携带非零 Range；最终字节与原始文件一致 |
| 多分片中一个分片中断 | 保留可复用进度，不重复完整下载 |
| 403 后刷新 | 使用 taskId 请求业务服务，OSS 请求不带 API Key，刷新后继续有效进度 |
| 刷新后再次 403 | 按本轮预算结束，不循环刷新 |
| 链接变但文件未变 | 校验一致后复用 checkpoint；不得仅因签名变化丢弃全部进度 |
| 文件 ETag/长度改变 | 不拼接不同版本的内容 |
| Range 被忽略或响应错误 | 安全回退或失败；错误 Content-Range 不落盘为成功 |
| 慢速持续传输 / 完全停滞 | 区分进展与停滞；总预算最终收敛 |
| 本机代理关闭、VPN/TUN 切换 | 保留代理降级；可恢复中断走重试；真机补充验证 |
| 同 recordingId 新写入、账号切换 | 旧下载/刷新回调不能覆盖新任务 |
| 重启 | 保留 taskId 等索引信息，恢复流程可重新下载；不宣称跨进程保留片段 |
| 迁移上传/下载回归 | 原迁移测试继续通过，不新增 STS 泄露或清理行为 |

除单元测试外，需运行真实 daemon 的旧/新请求模拟，并在同一文件下载中注入断流，检查状态、请求 Range、最终文件 hash。真实 App 创建的 RECORDING taskId 还需服务端联调；模拟接口不能代替这项验收。

## 9. 实施顺序

1. 抽取签名 URL 适配与 SDK 下载器，先让迁移测试保持通过。
2. 录音接入通用下载器，补旧 URL 回退、代理兼容和下载预算。
3. 接入可选 taskId 的持久化、刷新及回显，维持原有去重与状态协议。
4. 跑全量 Go 测试、race 检查及 daemon 模拟；再做真实 OSS/VPN 联调。

首期不增加跨进程 checkpoint、不改事件名、不恢复 HTTP 录音入口。实现不代表已合并或发布。


## 10. 本次验证结果（2026-09-29）

- `go test -race ./...`、`go vet ./...`、`go build ./cmd/yc` 通过。
- 本地 HTTP 模拟覆盖 SDK 中途断流续传、403 最多一次刷新、刷新后 checkpoint 复用、ETag 改变重新下载、响应头/停滞超时、零进展限制、刷新地址禁止重定向。
- 旧 URL 的 200 单流回退、本机代理拒绝后直连、404 不重试且原文件不受损测试通过；迁移上传/下载原测试通过。
- taskId 持久化、结果/事件/查询回显、仅文本更新保留、旧 App 新 URL 清空、已有音频复用，以及凭据/环境切换保护测试通过。
- 使用临时隔离目录启动编译后的 daemon，分别发送旧 App（无 ossTaskId）和新 App（带 ossTaskId）请求；各下载 18,700,000 字节并注入断流，均观察到非零偏移续传、最终 downloaded 和非空 audioFile，文件 SHA-256 与源文件相同。测试结束后已停止该 daemon，不替换现有安装。
- 部署上传工具未修改。真实 App 创建的 RECORDING taskId 是否可调用服务端 `/download-url`，以及真实 VPN/OSS 网络环境，仍需联调；本地模拟不替代这两项验收。
