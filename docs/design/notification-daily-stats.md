# 通知每日摘要索引

通知按现有 CLI 主机本地日期文件维护可重建的摘要索引：

```text
profiles/<profile>/notifications/
  YYYY-MM-DD.jsonl
  .stats/YYYY-MM-DD.json
```

索引本身由通知存储层维护，新增的[资产每日汇总接口](assets-summary-v1.md)复用此能力。
不变更通知原始格式、日期归档规则、去重或上传回执。

## 内容与口径

每个索引包含 `schemaVersion: 1`、`date`、`timeZone`、`count`、`latest` 和 `source`。

- `date` 对应已有日期文件。正常上报按通知 timestamp 转换为 `time.Local` 后划分日期，
  不按上传接收日统计；timestamp 按上报值保留，包括 UTC 的 `Z` 表示。
- `timeZone` 为 Go 的主机本地时区名称，系统默认配置下可能为 `Local`，不保证是 IANA ID。
  不支持通过本索引换算其他时区的一天，也不重排主机更换时区前的历史日期文件。
- `count` 为该文件内有效通知条数，包含当前 profile 的全部来源以及历史导入数据。
  有效通知须为合法 UTF-8 JSON 对象，非空字符串 `appName` 和合法 RFC3339 时间戳必填。
  可选字段类型异常不排除整条记录，读取时该字段回退为空；不是文件行数或去重键数量。
  资产列表中的超大行占位不是可验证的有效通知，本索引不按占位数统计。
- `latest` 为 timestamp 对应的真实时间点最大的一条完整 `StoredNotification`；
  同时刻取文件位置靠后的一条。正常增量与重建采用同一规则，保留来源及导入标记。
  空日期返回 `count: 0, latest: null`。索引只复制一条通知，不复制完整日文件；
  大小仍会受这条通知正文长度影响。
- `source` 保存源文件名、字节数、纳秒修改时间，读取时校验。
  `.jsonl` 存在时优先，旧 `.json` 数组为回退，两者不重复统计。

原始数据是唯一事实来源，索引可安全删除。源文件元数据用于失效检测，
不支持外部修改正文后刻意保留相同文件大小和修改时间。

## 写入与恢复

普通上报与 `transfer` 导入共用 `Storage.flushDay`：

1. 在已有存储锁内取得有效摘要基线；没有索引时只重建该日期。
2. 原始通知成功落盘后，只累计本批真正新增的有效记录，并比较最新时间。
3. 用现有原子写入工具保存索引，目录权限 0700、文件权限 0600。

重复、非法时间和落盘失败的通知不按请求条数累计。索引写入失败不改变上传成功结果；
丢弃失效索引并记录不含通知正文的诊断，下一次查询重建。数据写入与索引更新之间
进程退出时，旧索引与源文件元数据不匹配，下一次读取重建。

落盘失败、旧格式损坏隔离和过期清理同步失效或删除对应摘要。
首次写入旧格式日期时沿用原有 JSONL 转换流程，再更新源文件信息。
不会在 CLI 启动时扫描全部历史数据。

## 内部读取

```go
stats, err := storage.ReadDailyStats("2026-10-30")
```

方法内部持有现有存储锁，不可在 `WithReadView` 回调中再次调用。
HTTP 汇总通过 `ReadDailyStatsContext(ctx, date)` 读取，支持取消，冷重建最多 32 MiB；
`ReadDailyStats` 使用相同冷读上限。已有有效索引可读取更大的日期文件，
索引自身读取最多 32 MiB；普通写入的基线维护不受此冷读限制。
命中有效索引只读取源文件元数据和对应摘要，不扫描正文或其他日期，
也不会将历史整日数据装入 `dayCache`。

缺失、损坏、旧版本或源文件变化时按该日期重建。JSONL 坏行与不完整尾行跳过，
合法的无末尾换行记录正常统计；旧数组结构损坏和真实源文件读取失败返回错误，
不转换为零，也不在查询中隔离、迁移或修改原始数据。
源文件不存在返回空摘要，并移除遗留索引。缓存不可写时仍可返回已验证的源数据结果。
源文件和 `.stats` 目录的符号链接不作为合法统计路径。

## 验证

`internal/notif/daily_stats_test.go` 覆盖增量、去重、多来源、迟到上传、同时间点、
UTC 时间戳与本地跨日、重启、历史重建、坏行/长行/尾行、旧格式、索引失效、
导入及回滚、缓存失败、源文件失败、清理/隔离、符号链接及并发读写。

本机 darwin/arm64（Apple M5 Pro）短正文模拟数据，200ms 基准采样：

| 当天条数 | 有效索引查询 | 删除索引后重建 |
| --- | ---: | ---: |
| 200 | 0.021 ms | 0.865 ms |
| 10,000 | 0.022 ms | 32.258 ms |

重建项包含索引删除和原子保存；数据与文件系统缓存均为本机测试环境，
不代表其他设备或长正文数据的延迟承诺。可通过以下命令复测：

```sh
go test ./internal/notif -run '^$' -bench '^BenchmarkReadDailyStats$' -benchtime=200ms
```
