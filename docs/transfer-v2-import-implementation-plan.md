# CLI v2 数据迁入实施计划（IMP）

状态：本地 v1/v2 导入和 Skill 已实现并通过测试，尚未发布。云端异步履约对接、无影实际 Agent 熟悉行为及 10 GB 性能测试仍待联调。
日期：2026-10-26。
基线：CLI 当前本地提交 `a1b877c`；源插件 `release/1.20.0` 的 `9dbf0ad`、`e80fabc`。本稿基于本地代码核对，未宣称远端已同步或服务已联调。

## 1. 本次要实现什么

接收 OpenClaw 全量 v2 包，兼容此前 v1 包。命令、迁移 Skill 和后续异步迁入入口共用一套导入服务。

- 通知、录音、网页、图片：复用现有迁移业务逻辑和当前 profile 的数据目录，不迁到 workspace 充当普通文件。
- 新增的设定、长期记忆、历史会话、工作文件和定时任务资料：迁入当前无影运行用户 home 下的 `wuying-agent-workspace`。独立技能放 Claude 对应 Skill 目录；每日日志放对应项目的 Claude memory 目录，按第 3 节执行。例如 admin 用户为 `/home/admin/wuying-agent-workspace`；不存在则创建。
- 其他 Agent：仅恢复为隔离备份，不合并进主 Agent、不自动加载技能或启用任务。
- 历史 OpenClaw 会话作为资料查询，不转换成 Claude 原生会话。新增读取位置索引，让 Agent 能找到历史资料。
- 不迁入凭据、插件安装、插件依赖技能和已排除的知识库。源端只导出 `enabled=true` 的定时任务，目标端也核对该条件。

“数据导入”与“熟悉数据”分开执行和验收。导入负责数据落盘；熟悉由 Agent 更新记忆、逐项恢复缺失的定时任务和保存资料位置索引。定时任务尚未恢复不反向改变已完成的数据导入状态，熟悉结果不向履约维护完成状态。

### v2 包处理

输入为 `manifest.json + blobs/<sha256>`。每个文件含 `category、scope、path、hash、bytes`；`sources.originalRoot` 只作来源说明，绝不作为目标写入路径。

1. 校验 schema、允许的分类、字段类型、文件数和大小上限、blob 长度及 SHA-256。相同 blob 可以恢复成多个逻辑文件。
2. 以 `(category, scope, path)` 标识逻辑文件；同标识不同内容、缺失 blob、非法路径或未知分类均明确报错。与目标已有文件的重名按第 3 节处理，不把正常重名当成坏包。
3. 在私有 staging 恢复受控逻辑视图；按分类分流到业务记录适配器或 workspace 文件计划。不得直接按 `path` 把所有类别混在同一目录。
4. 保留现有路径穿越、链接、大小和损坏包校验。全量数据上限暂按原始 10,000,000,000 字节；下载上限包含归档头余量，解包有总量及膨胀比限制。macOS/Linux 已在解包、目录暂存、workspace 及业务附件复制前检查空间并留 64 MiB；下载峰值及不同挂载点累计空间仍需 10 GB 实测，空间检查不能替代写入错误处理。
5. `capabilities` 只有在 v2 导入及下述必需校验完成后才声明支持 schema 2，旧版 schema 1 继续保留。

### 旧业务数据复用

v2 的原始日文件／业务索引不是 v1 `Record`，不能直接交给旧合并函数，也不能覆盖目标索引。适配器从已校验视图构造原有 Record/Asset，再进入现有预览和合并流程，不再实现第二套去重算法。

| 类别 | 适配入口 | 保留的行为 |
|---|---|---|
| 通知 | 日文件转记录；按现有内容身份和规范化规则生成记录 | 目标时区重新分桶、重复跳过、保留现有通知、历史通知不进入自动记忆消费 |
| 录音 | `index.json` 中录音及引用文件映射成记录和资产 | 复用补附件与冲突规则；音频、转写、摘要按真实索引字段定位，导入后重写为目标相对路径 |
| 网页／图片 | 业务索引及引用内容转记录和资产 | 复用既有身份、去重、补充及目标存储规则 |

重点：录音摘要不得重新按标题猜文件名；旧绝对引用只能通过对应源根目录映射到已校验的包内文件，不允许读取源机器路径。所有业务引用必须有可验证映射。

通知 `.ids/`、`.keys/` 经存储层 `ImportTransferSeen` 合并到 `.transfer-seen/<day>.json`，不覆盖目标日文件和原有索引。先导入当前通知，成功后追加源端已见 ID 与内容指纹；这些事实独立于启动时重建的 `.keys`，防止已删除通知重推后复活。已补重启后按 ID／内容去重及 ImportDay 回灌测试。源端不含正文的 ID 只保留源日期；含时间戳的内容指纹跨时区仍可去重。

v2 不携带 v1 完整的跨迁移来源身份时，不伪造已有 origin。新来源标识及 RecordVersion 沿现有规范化算法生成，验证同包重试和不同包中的同一业务数据均不重复写入；该适配规则在开发时固定为测试样例。

## 3. 目标目录与 Agent 可见性

`W` 表示可信运行用户的 home + `/wuying-agent-workspace`，无影例子为 `/home/admin/wuying-agent-workspace`。使用 daemon 进程的 home 并校验它是绝对目录；请求不能指定 home，且不从迁移包或源用户名推断目标。部署应确保 daemon 在目标用户下运行（例如 admin），避免以 root 启动后写入 root 的 home。当前本机鉴权不额外携带调用者 UID。

已实现的落盘约定：

| 包内类别／相对路径 | 目标位置 | 处理 |
|---|---|---|
| `workspace` | `W/<path>` | 保留项目目录、文档和附件相对结构 |
| 长期 `memory`：`MEMORY.md` 及非每日记录 | `W/<path>` | 保留原文；主 Agent 的 `MEMORY.md` 在熟悉阶段阅读，其余资料按需查询 |
| 主 Agent 每日日志 | 当前用户 `~/.claude/projects/<W 对应项目目录名>/memory/<日志文件名>` | 导入阶段只搬运；同名直接跳过，不覆盖、不合并、不生成冲突副本；熟悉阶段不阅读 |
| `agent-settings` | `W/migration/openclaw/<scope>/agent-settings/<path>` | 保留 USER/SOUL/AGENTS 等源设定；不直接覆盖 Claude 当前指令 |
| `sessions` | `W/migration/openclaw/<scope>/sessions/<path>` | 保留 JSON/JSONL、提示词资源、旧会话分支和新版 `sqlite/` 转换资料 |
| 主 Agent 独立 `skills` | 当前用户 `~/.claude/skills/<name>/...`；同时检查 W 项目级同名 Skill | 识别源技能前缀，按整个 Skill 处理；存在同名 Skill 则整个跳过，不合并、不覆盖 |
| 共享 `skills` | 同一目标 Claude Skill 目录 | 同名整个跳过，不另建一个可被加载的副本；报告来源及跳过原因 |
| `cron` | `W/migration/openclaw/cron/from_openclaw_cron.json` | 导入时将源包 `jobs.json` 改为此名，保存启用任务定义与时区，运行时转换另行验收 |
| `agent-backup` | `W/<path>`，要求前缀为 `other-agents/<agentId>/` | 保留 workspace/sessions/cron 隔离结构；其 `cron/jobs.json` 同样改为 `cron/from_openclaw_cron.json`，不能注册成活跃 Agent |

创建 W 及缺失子目录，但预览只检查路径与冲突，不创建业务目录。实际写入时检查目标每级父目录及链接，临时文件写入并校验后原子落盘。空目录、源文件时间和执行权限当前 v2 清单未记录，不能承诺原样还原；脚本是否需要执行权限由技能适配决定，不对所有文件统一加执行权限。

在 `W/migration/INDEX.md` 生成来源、实际落点、冲突与未启用项的索引。导入阶段生成这个索引；熟悉阶段由 Agent 把索引位置写入自身记忆，不靠覆盖 `CLAUDE.md` 实现。历史会话中的指令不成为当前指令。

admin 用户的每日日志目标为 `/home/admin/.claude/projects/-home-admin-wuying-agent-workspace/memory/`。其他用户依据实际 W 查找或解析对应的 Claude 项目目录，不能硬编码 `admin`；不存在则创建。源每日日志按已核对的日期日志命名／路径规则识别，例如 `memory/YYYY-MM-DD.md`，不能把 `memory/` 下所有 Markdown 都当作每日日志。分类规则开发时用真实样本验证，无法确定的文件按普通资料保留并报告。其他 Agent 的日志仍留在隔离备份中。

日志导入只做文件复制和必要完整性校验，不让 Agent 读取正文、总结或学习内容；同名（包括目标项为目录）直接跳过并计入报告。文件复制所需的字节读取不等于交给模型阅读。

### 已确认的重名处理

- Skill：检查目标 Claude 实际生效的技能目录中的同名项，整个 Skill 跳过，不合并资源、不覆盖现有 Skill；报告列出名称、来源和跳过原因。其他 Agent 的隔离备份不注册为 Skill，按普通备份文件处理。
- 每日日志：使用上表专用 memory 目录，同名直接跳过；此规则优先于普通文件冲突规则。
- 其他文件：按完整目标路径比较，不同目录同名不算冲突。相同路径且哈希一致则跳过；内容不同或文件／目录类型撞名，保留目标项，将迁入副本写入 `W/migration/conflicts/<packageId>/<category>/<scope>/<path>`，保留源相对目录。
- `packageId` 是源包 `manifest.json` 中的包编号，不由用户填写。先校验它及所有路径段，再用于落盘。分类与 scope 一并保留，避免不同来源的冲突副本再次撞名。
- 同包重试使用相同冲突落点；副本已存在且内容一致则跳过，内容不同则报告目标已变化，不覆盖、不不断生成后缀副本。
- 索引记录原目标与实际保存路径。结构化引用在可验证的情况下更新为实际落点；普通文档中的路径不盲目全文替换。无法保证引用有效时报告未完成，不声称已恢复可用。
- `from_openclaw_cron.json` 仅是导入后文件名，源包及源端 `jobs.json` 不变；重名时仍执行上述比较与隔离规则。
- 录音、通知、网页、图片继续用原有业务去重、补附件和冲突处理，不改成这套普通文件冲突规则。

主 Agent 工作文件与上述保留目录可能撞名，必须在写入前检测。导入器管理的索引和冲突区域不得被包内同名路径覆盖或冒充。原始 `sources` 未提供逐文件 sourceId，不能仅靠 originalRoot 猜来源；现有 category/scope/path 足以确定的映射按表执行，出现无法唯一定位的输入时报告协议缺口，不猜路径。

## 4. 执行、恢复与异步接入

### 共用执行流程

`下载／本地暂存 → v1/v2 校验 → 业务记录与文件预览计划 → daemon 串行执行 → 校验落点和引用 → 写报告 → 汇总结果`。

- 保留 `--file` 只预览、`--task` 默认执行、`--local + --plan` 执行、`--resume` 续跑的既有语义，不要求用户新增一套命令。
- 文件不存在则新增；同内容跳过；不同内容按第 3 节持久保存到 conflicts 目录。Skill 同名整个跳过，每日日志同名直接跳过。迁移索引只更新自身管理的内容，不覆盖用户其他文件。
- 业务记录和新文件的执行结果纳入同一 report。记录文件路径、哈希和已完成步骤，失败后仅接续未完成项；不对跨业务存储假装提供整包事务回滚。
- `SUCCEEDED` 需满足本次约定的必需步骤；已按约定跳过同名 Skill／每日日志、跳过同内容文件或完整保存冲突副本且引用有效，不单独判为失败，报告仍列明处理结果；旧业务合并冲突、缺失引用或必须恢复却未完成的项目返回 `PARTIAL`／失败。报告区分“已保存资料”和“已注册技能”；定时任务文件的导入不代表已创建任务，创建属于独立的熟悉阶段。
- 沿用成功后清理 staging、部分失败保留 staging 和 report 的机制；workspace 的已迁入文件及 conflicts 中的副本不是临时数据，不能随清理删除。

### 后续异步入口

履约通过 relay-go 定向通知目标 CLI，入口建议 `/transfer/import/start`，具体请求及回报按需求二已约定的履约契约对齐，本文不新增业务字段。履约在备份就绪且目标可用后通知，CLI 不轮询备份是否就绪。

新增入口只接受 transferId 和 fileTaskId，复用认证 Relay。履约核对任务、目标绑定、文件归属、上传完成和有效期；IMPORT_STARTED 成功后，CLI 用 fileTaskId 调 download-url 下载。不能直接复用目前仅允许本机调用的 `/transfer` 权限，也不接受远程任意文件路径或命令。

本地 CLI/daemon 通过 `YOOOCLAW_TRANSFER_TIMEOUT`（Go duration，如 `6h`）配置，缺省 6 小时；当前每次本机调用有独立 deadline，复制／解包支持取消。后续异步任务须首次受理固定截止，重复受理不延长。履约保留服务端超时判定；本地超时用于中止资源消耗。10 GB 实测后调整，配置不硬编码在 Skill。下载进度按实际字节统计，沿现有讨论的至少 15 秒且至少增长 1 个百分点节流。

导入执行名额与结果回报分开；永久回报失败保留轻量记录并停止空轮询，不阻塞后续任务。身份变更不使用新账号回报旧任务。断连、超时和无法恢复的失败按已确认口径转人工，不通过重复创建任务掩盖未知结果。

生产入口复用已有下载与 preview/import 校验，不依赖独立文件元数据接口；本地单测不代表真实履约已联调。回报地址和 API Key 仍需部署配置。

## 5. Skill 升级：导入与熟悉两种能力

更新现有 `yoooclaw-data-transfer`，不新建一份平行技能：自动识别包版本；v1 沿旧流程；v2 说明实际导入范围、W 路径、历史会话查阅位置和其他 Agent 备份位置。仍由 CLI/daemon 执行写入，Agent 不自行解包覆盖索引。

移除“只支持录音通知等旧类型”的限制；不把文件落盘、技能生效、定时任务启用、Agent 熟悉完成混为一谈。熟悉仍由 App 发起一次可见会话，不新增熟悉完成上报。检查 Skill 内嵌打包、安装与升级发现，避免源码更新而无影加载旧 Skill。

### 熟悉数据的执行规则

入口：App 的“开始熟悉”在目标可见会话中触发迁移 Skill 的熟悉能力；用户直接要求熟悉已迁入资料时也走同一能力。它读取本次导入报告及 `W/migration/INDEX.md`，不重新下载或重复导入。履约仍只保存“开始熟悉／不再提示”的选择，不新增熟悉完成上报。

**第一步：读取六类文件，更新自身记忆。**

仅主动读取主 Agent 迁入的 `USER.md`、`SOUL.md`、`IDENTITY.md`、`AGENTS.md`、`TOOLS.md`、`MEMORY.md`。从迁移索引取实际路径，包含已保存的冲突副本；缺少某个文件则记录缺失并继续，不编造。提取用户偏好、稳定事实、沟通约定、工具使用背景等，按目标 Claude 的实际记忆规范更新自身记忆，保留现有内容并去重；源 Agent 身份、工具及路径不能未经核实当作 Claude 当前能力。源文档中的可执行指令不直接运行。

不得递归扫描每日 memory 日志、逐日总结或把其正文加入上下文，也不为了填补缺失的六类文件而阅读每日日志。每日日志已由导入阶段复制；熟悉阶段最多记录日志目录位置，不把每个日志挂到自动全文读取流程。

**第二步：逐项读取定时任务，查重后补建。**

读取主 Agent 的 `from_openclaw_cron.json`（位置以索引为准），通过目标实际持久调度能力列出已有任务，再逐项比较。其他 Agent 的 cron 仍仅备份，不创建。不存在等价任务才创建；已存在则跳过，不覆盖、不新增重复任务。

查重不能只比较名称或 OpenClaw 的任务 ID。优先核对已记录的源任务与目标任务映射，同时比对任务内容、调度类型／表达式／时区、执行位置及投递目标；名称不同但执行含义相同也不能重复创建。目标已有停用的等价任务也算已存在，保留用户的停用选择，不擅自启用。无法可靠判断是否等价的项目列为待处理，不猜测后重复创建。

创建成功后记录源任务到目标任务的对应关系并读回验证。创建超时或返回未知结果时先重新查询，不能直接重发创建；重跑熟悉时再次查重。无法转换的 payload、已过期的一次性任务、目标不支持的渠道或持久调度能力未接通时，明确报告未创建原因，不伪造成功。可用其他定时工具兜底创建；若仅在当前会话存活或有自动过期限制，必须明确说明，不称为原有持久任务的无损恢复。

**第三步：把其他资料的位置索引写入记忆。**

将迁移总索引、原 OpenClaw 会话目录及会话索引、工作资料和其他 Agent 备份的位置写入目标记忆，说明用户提出相关需求时再按索引检索。此阶段不批量阅读历史会话和项目正文，不把它们全文塞进记忆。记录的是已校验的实际落点，不能照抄源机绝对路径；重复熟悉更新同一索引引用，不不断追加重复条目。

向用户汇报本次记忆更新、任务新增／已存在跳过／待处理数量和资料索引位置。日志同名跳过、Skill 同名跳过与普通文件冲突落点沿用导入报告。这里是可见会话内的执行反馈，不是新的履约熟悉完成状态。

## 9. 2026-10-26 接入补充：调度工具与下载进度

- 无影 runner 0.3.72 内置 `ac_scheduled_tasks`；目标机当天真实 Claude 工具记录显示 `mcp__ac_scheduled_tasks__scheduled_task_create` 创建成功，返回平台任务 ID、ACTIVE 和下次执行时间。熟悉提示词改为优先使用该工具及同服务查询接口；必须查重、转换 cron 格式并读回。裸 `claude -p` 未自动加载此 MCP，runner 的内部端点没有执行授权会返回 403，不能把裸 CLI 验证当作托管会话验证，也不能复制别的会话授权。首选工具缺失时继续查找其他可用调度工具，包括原生 CronList／CronCreate；查重后创建，支持 durable 则启用。工具存在 7 天有效期或会话存活限制时明确告知，不宣称无期限等价恢复；不能仅因首选工具未加载而停止。
- `transfercloud.DownloadWithProgress` 已接入原 OSS 下载器；SDK 的绝对已写入字节用于计算进度，重试不累计流量，只保留最大已知进度。并发回调只更新一个最新值，独立协程串行 PUT；默认 15 秒加不足 1 秒错峰、至少增长 1%；无变化不发心跳；失败退避，上限为 2 分钟与配置间隔中的较大值；明确拒绝停止重试。0 可立即上报，100 在最终本地文件保存成功后上报；100 不是迁入成功。
- 调用沿接口草稿 `PUT <履约 transfer 前缀>/{transferId}/download-progress`，Body 仅 `progress`；识别 `success=true`、`code="000000"`，允许 `data=null`。复用 API Key，禁止转发重定向；网关前缀须部署配置且与当前 API 同源，不从包里取地址。单次上报最多 3 秒，下载期间不阻塞文件传输；结束等待至多当前请求及最后一次请求。上报失败通过 `progressWarning` 返回，不把导入判为失败。
- 联调入口：`yoooclaw transfer import --task <fileTaskId> --transfer-id <履约transferId>`；部署设置 `YOOOCLAW_TRANSFER_REPORT_BASE_URL` 为已确认的 HTTPS 履约 transfer 前缀，可设置 `YOOOCLAW_TRANSFER_PROGRESS_INTERVAL`（Go duration，至少 15s）。两个 ID 不混用；不提供 transferId 的旧手动迁移保持原行为。此入口用于已授权的本地联调，不代替履约许可，也不开放远程自动迁入。

## 10. 2026-10-27 异步入口与回报

- 生产 daemon 启动时创建 `transferjob.Service`，新增 `POST /transfer/import/start`；仅复用已认证 Relay 的目标凭据标识，Body 仅 `transferId/fileTaskId`，不允许路径、URL、命令或额外字段。快速成功响应使用 `success/code/message/data` 包装，仅代表任务已落盘。
- 部署配置 `YOOOCLAW_TRANSFER_REPORT_BASE_URL`；配置无效时入口 503。缺失／变更的凭据不能受理旧任务，需要重新启动绑定。没有新增独立授权查询。
- 同任务同参数重复受理不重新导入、不延长截止；不同文件返回 409。一次只执行一个导入；待回报结果不占用导入槽。
- `IMPORT_STARTED` 成功后才执行下载流程；下载及校验成功报 `DOWNLOAD_COMPLETED`，随后复用原 preview/import。PARTIAL 按失败处理。最终结果先落盘，再报 `IMPORT_SUCCEEDED/IMPORT_FAILED`，上报失败不重做导入。
- 结果每轮最多首次＋3 次尝试，明确拒绝不重试；失败留本地记录，重启只补报原结果。运行中重启按中断失败处理，不静默重放可能已写入的数据。临时下载文件在正常成功／失败退出时清理。
- 首次受理固定本地截止，下载、校验、预览、导入共享一个上下文；默认六小时，可用 `YOOOCLAW_TRANSFER_TIMEOUT` 调整。终态回报另用短超时，避免任务超时后无法回报失败。
- **按最新确认取消独立元数据依赖：**生产执行器直接使用 fileTaskId 获取下载地址，下载后执行现有 preview 校验，通过后回报 DOWNLOAD_COMPLETED，再执行 import。保留压缩包、清单、blob 长度／哈希及路径检查；不要求服务端提供整包 SHA-256。履约负责派发前核对归属、上传完成和有效期。
- 本地验证：全仓 `go test ./...` 通过；异步任务、事件客户端和 daemon 的 race 测试通过。覆盖重复受理、参数冲突、超时、重启中断、凭据变化、回报失败不阻塞后续任务、包校验失败／状态回报拒绝不导入。未部署默认云机 daemon，未做生产履约联调。

两个 ID 的职责：`transferId` 是履约流程 ID，用于去重和回报；`fileTaskId` 是文件服务备份 ID，用于下载。履约保存关联，Relay 通知不传下载 URL。
