# NanoShell 小程序交付

交付链：需求 → Wasm 源码 → 候选安装包 → 自动验收 → 用户试玩 → 发布。
本 skill 内置 SDK 快照，可在没有原始仓库权限的电脑上工作。目标是已经集成兼容 NanoShell Host 的硬件。

## 执行节奏

按当前阶段读取对应参考文档；脚本优先按文档直接运行，具体报错或接口歧义出现后再定位相关实现。每次追加源码阅读都对应一个明确问题，确认答案后立即用于修改或验证。

若使用任务列表，满足本阶段完成条件后立即更新状态并推进下一步。持续工作时约每 60 秒简短说明已完成的产物、当前动作和实际阻塞；耗时命令使用平台支持的可轮询执行方式，保留日志和退出码。连续阅读或分析仍无文件修改、构建或测试进展时，收敛到最小可验证改动；确需继续调查则说明阻止实现的具体问题。准备、实现及验收之间自主推进，用户试玩认可仍按第 5、6 步执行。

## 1. 确定验收目标

从用户需求提取应用名称、核心操作、成功/失败状态、重开或恢复方式、存储要求；将这些写成工作目录中的 `acceptance.md`。普通玩法默认采用内置 SDK 的设备配置；涉及其他屏幕、硬件能力或 Host 版本时先确定兼容性。

需求涉及灯效、振动、通知、BLE、电池、录音、屏幕、计时或存储时，读取 [设备交互与验收](references/interactions.md)，将触发条件、反馈参数与退出清理写入验收目标。当前目标设备均有马达，无需设计无马达分支。

**完成条件：** 每项可见需求都有可观察的验收结果；已确定目标设备配置。只有影响实现的缺失信息才向用户询问。

## 2. 准备独立项目

读取 [环境与命令](references/environment.md)，运行 `pipeline.py init`，在用户工作区创建项目，再执行 `dependencies.py setup` 按项目锁解析共享依赖。修改既有应用时沿用原目录和稳定 App ID。

**完成条件：** 项目包含 SDK、示例、预览器；Python、Wasm Clang/链接器、Node、Playwright Chromium 均可用。依赖缺失时先解决可安装的本地依赖，确实受阻则报告具体缺项。

环境检查通过即进入实现；应用设计、Host 源码调查和玩法测试属于后续阶段。

## 3. 实现并构建候选包

编写前读取项目的 `guest/sdk/ns_guest.h`、`docs/host-api-v1.md` 和 `docs/design-notes.md`；最小应用参考 `hello_tiny.c`，按键相位参考 `hop.c`，存储参考 `counter.c`。

从最贴近需求的示例起步，先写出包含画面、核心输入和退出路径的最小版本并立即编译，再逐项补齐 `acceptance.md` 的功能。首次构建的目标是尽早验证接口与工具链，完整需求仍须全部实现并验收。预览器内部实现仅在公开接口和示例无法回答具体问题，或实际运行报错时按相关函数查阅。

在 `guest/wasm/<name>.c` 实现应用，导出 `start`；使用 SDK 的屏幕、按键和资源约束。逐帧 heartbeat，BACK 正常退出。运行 `pipeline.py build`，它生成 `dist/<name>.nsp` 和目录清单，预览器直接读取该设备包。构建或验收失败时修复源码并从此步重跑。

**完成条件：** 打包命令成功、候选 `.nsp/` 包完整，预览器引用的字节与包内 `app.wasm` 一致。

## 4. 自动验收

读取 [自动验收](references/testing.md)，按 `acceptance.md` 编写项目专用场景并运行 `test_app.mjs`。检查截图中的布局、文字、障碍或控件，修复视觉问题。通用冒烟测试不替代玩法验收。

**完成条件：** 通用测试及每项需求对应的自动断言通过；截图已查看；测试报告绑定当前安装包、源码、测试场景和预览器的哈希。硬件专属行为单独标注为待真机验证；浏览器结果只证明浏览器 Host 下的行为。

## 5. 提供试玩

读取 [试玩服务与打开方式](references/preview.md)，按运行环境托管项目预览服务。预览直接运行已验收候选包；给用户实际验证的可点击地址、操作说明、测试摘要、待真机验证项和报告位置。云电脑交付时明确提示：**请选择“安全方式打开”，不要选择“新窗口打开”。**

**完成条件：** 托管服务在启动命令结束后的独立检查中仍可访问，浏览器能运行并操作目标应用，已说明在哪台电脑及用哪种方式打开。仅启动瞬间 HTTP 200 不算完成。请用户试玩确认；等待明确认可当前版本。用户要求调整时回到实现步骤，旧版本认可不沿用。

## 6. 用户确认后交付

只有用户认可当前候选版本后，读取 [发布与安装](references/release.md)。发布脚本核对报告与候选包一致后生成 ZIP、校验文件和安装说明，再按发布文档调用 `yoooclaw nanoshell publish` 注册到 CLI 的持久目录，供 App 列表和下载接口使用。

**完成条件：** 已成功注册到目标 profile 和客户端，返回 packageId；用户获得已测试的 `.nsp` 文件夹压缩包、SHA-256、兼容性及安装步骤。发布过程复用候选包，任何源码或产物变化都重新构建、验收和试玩。
