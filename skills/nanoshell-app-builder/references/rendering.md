# 硬件画面与试玩一致性

## 字体与尺寸
- 默认设备为 240×120。先在此逻辑分辨率安排文字与图形，不以放大的网页截图推断真机字号。
- 当前 NanoShell LVGL draw_text 实现使用 LV_FONT_DEFAULT；scale > 1 只增加字间距，不放大字形。不要用 scale 冒充大字体。后续固件若改变此行为，应核对目标实现后更新判断。
- 大数字可采用七段矩形，大标题可采用随包提供的点阵字模；普通说明采用目标固件支持的字体。固件系统界面支持中文，不等于 Guest 绘制路径具备中文字库。中文需确认 Guest 字体链路或嵌入所需字形，并重新检查包大小；不要未经用户同意更换语言。
- 点阵渲染仍需字形覆盖，不自动解决中英文兼容问题。随机、动态和最长文案均需检查；空文本不应绘制问号占位符。

## 布局与像素图形
- 对齐使用实际可见边界计算：例如计时数字高 27、小猫高 35，可共用垂直中心，不能仅给相同的 y 坐标。装饰与说明行也按实际字形中心对齐。角色眨眼、跳动等状态都应留出空间。
- 小屏优先使用整数坐标和清晰的像素轮廓；矩形/点阵绘制能保持跨 Host 一致。图片采用目标分辨率或整数倍缩放，避免反复缩放。不要强制所有应用采用同一种美术风格。
- 文字宽度按实际字形推进计算；例如 UNSCII8 的 18 个 ASCII 字符约 144 像素。为右侧图形留间距，不仅检查字符数。动态中文按 UTF-8 字符边界分页，不能任意截断字节。

## 试玩与验收
- 浏览器采用与目标固件一致的字形及定位规则；不可用浏览器平滑字体替代后宣称真机效果相同。自行绘制大字需同时进入 Wasm 产物。
- Canvas 后备尺寸保持 240×120，关闭 imageSmoothingEnabled，使用 image-rendering: pixelated；显示尺寸尽量使逻辑像素对应整数个物理像素（考虑 devicePixelRatio），避免 CSS 拉伸与抗锯齿。极窄容器可滚动，不溢出操作控件。
- 检查待机、运行、暂停、完成、错误及最长文案截图，确认字号、居中、间距、遮挡和像素边缘；熄屏截图不能作为布局验收。动画检查起始、中间和完成帧。
- 控件提示必须匹配程序实际按键语义；没有触屏事件时不要写成点击画面即可操作。试玩通过不能替代真机字体和尺寸验收。
