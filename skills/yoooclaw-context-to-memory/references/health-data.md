# Health memory

Use `sync next --source health-data` and token confirmation from the parent skill. Each item is the latest snapshot for one business date. `data.header` supplies date/timeZone/provider/updatedAt; `data.items` supplies ordinary metric/name/value/unit; `data.sleepSessions` supplies v3 sleep summaries and segmentCount. Query `health-data get --date YYYY-MM-DD` only when full stage detail is needed. The batch version covers complete segments, even though the memory batch contains summaries. If a fresh query differs from the pending snapshot, do not claim its new content was acknowledged by the old token; process the next revision separately. Previous data is the last confirmed snapshot. Timestamp-only updates do not produce new consumption.

Only v3 is supported. Update the existing dated health record when metrics or sleep sessions change; retain evidence of revision where useful. Missing metrics mean unread/unknown, not zero. Sessions may change IDs when start time or sources are corrected: replace the dated snapshot, never append duplicate sleep. Empty days are not deletion signals; absent days do not erase historical memory. A day matching the source-local current day is partial as of updatedAt. Keep metric, unit, provider, and date when comparing; only compare equivalent definitions. Daily values can become dated records; durable trends need enough comparable observations and do not establish a diagnosis.

Before writing health memory, read [health query semantics](../../yoooclaw-context-query/references/health-data.md#metric-semantics).

Apply those definitions to both saved memory and the final reply: isPartial=false is not proof of a complete night or synchronized device data; unknownMinutes=0 is not proof of no missing data. Observation boundaries are not bedtime/rise time, time in bed, or a basis for sleep efficiency. Preserve source-local date/timeZone, provider and snapshot version with the dated record. Do not promote interpretations from a prior agent report into field definitions; correct conflicts against the source contract. During the parent's separate read-back step, verify dates, units, values and these meanings, then ensure the final reply agrees with the verified record.
