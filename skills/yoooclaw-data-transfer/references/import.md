# Import local data

1. Run `yoooclaw transfer capabilities --format json` on the target. If the daemon is not running, start it (`yoooclaw daemon start`); if it is too old (`YOOOCLAW_TRANSFER_UNSUPPORTED`), restart it (`yoooclaw daemon restart`). Do not write data files as a fallback.
2. Run `yoooclaw transfer import --file <package-directory> --format json`. `--file` only stages, verifies and previews; it never merges. It returns `localTransferId`, `planId`, per-action `counts` (`added`, `skipped`, `supplemented`, `conflict`), up to 50 conflicting records in `issues`, and a ready-to-run `nextCommand`.
3. Execute the approved plan with `yoooclaw transfer import --local <localTransferId> --plan <planId> --format json`. Preview does not imply permission to expand the data scope. When the user already authorized importing this package, proceed within that authorization.
4. Explain that imported notifications are available for queries but excluded from automatic notification-to-memory ingestion (`yoooclaw sync`). Existing local notifications are preserved. Notifications are re-bucketed by the target's own timezone, so day file names can differ from the source; timestamps keep their original value.
5. Report SUCCEEDED or PARTIAL from `state`. State is decided by what was actually written: `warnings` (carried from the export) and `targetWarnings` (unreadable target files skipped during preview) are reported separately and do not by themselves mean PARTIAL. Conflicting source records and attachments remain in the staged package; target records remain intact. Per-record outcomes are in `report.json` at `reportPath`.
6. For an interrupted/partial import, run the same local command with `--resume`; the report at `reportPath` carries the `planId` you need. If `YOOOCLAW_TRANSFER_PLAN_STALE` is returned before execution, the target's own copy of a planned record changed — take a fresh preview from the package and use the new IDs. Unrelated new notifications arriving on the target do not invalidate a plan.

On SUCCEEDED the staged copy is removed automatically (`staging: "cleaned"`). A PARTIAL or failed import keeps its staged package and `report.json` for retry; never delete those before the user has resolved the result. Staged copies that were previewed but never imported are pruned after 7 days. Never claim the cloud has been involved; this release uses local files only.
