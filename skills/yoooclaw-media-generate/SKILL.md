# 图片与视频生成

通过自有服务生成媒体，脚本仅依赖 Python 3 标准库。根据用户需求执行下方图片或视频分支；查询已有视频任务时直接使用任务 ID 查询。

## 共同流程

1. 确定内容和规格：图片选择档位；视频选择分辨率和秒数。缺失时询问用户，已有明确选择则沿用。面向用户用档位和规格描述能力，隐藏内部模型名称、供应商及路由。
2. 使用对应脚本的 `estimate` 获取报价。返回 `estimate_response.credits` 后，告知本次规格和预计总积分；估算失败或金额不明时停止生成。
3. 用户已知悉相同成本并选择生成时直接继续。规格或报价变化时重新告知并取得确认。只有已有授权才传 `--confirmed`，生成请求的规格须与估算一致。
4. 按分支的完成条件交付结果。优先在当前对话展示媒体，不能预览时提供结果链接。预计积分与实际扣费分开表述，当前生成响应不提供实际扣费金额。

### 媒体链接完整性

**图片和视频的展示、下载链接必须逐字使用接口返回的完整 URL。** 图片使用脚本返回的 `images[]`，视频使用 `video_url`；完整保留路径、查询参数和原有百分号编码，尤其是 `Expires`、`OSSAccessKeyId`、`Signature`。

- 只缩短 Markdown 的显示文字（如“下载图片”“下载视频”），链接目标保持原值。
- 不截断、不脱敏、不用 `…`、`...` 或 `%E2%80%A6` 替换任何 URL 内容；不改写签名参数，不向 URL 插入反斜杠或重新编码。
- 发送前逐字核对链接目标与脚本返回值。若只拿到被省略或脱敏的链接，重新读取原始生成结果；视频可查询原任务获取完整链接。缺失签名无法靠删除省略号恢复，不猜补链接，也不为此重新提交付费生成。

## 图片

当前支持文字生图，每次一张。让用户在下列两档中选择，仅说明已知价格，不捏造画质或速度差异。

| 用户选项 | 每张参考积分 | 脚本档位 |
| --- | --- | --- |
| 标准版 | 10.10 | `standard` |
| 专业版 | 25.25 | `professional` |

用本 skill 的绝对路径替换 `{baseDir}`：

```bash
python3 {baseDir}/scripts/image_generate.py estimate --tier standard
python3 {baseDir}/scripts/image_generate.py generate --tier standard --prompt '一只戴着墨镜的奶牛猫，坐在日落海边' --confirmed
```

生成接口同步等待，图片生成请求的网络超时为 300 秒。脚本从 `data[].url` 提取链接，返回：

```json
{"status":"success","images":["https://..."]}
```

**完成条件：取得有效图片链接并交付用户。** 超时或响应格式异常时先核实结果，避免重复生成扣费。目前只解析 URL 图片结果；尺寸控制、参考图编辑和批量生成尚未接入。估算的 `--n` 可计算多张费用，但生成命令仍每次一张，不将多张报价当作单次生成规格。

## 视频

确认分辨率和时长，缺少任意一项时询问用户。视频时长必须为 1–30 的整数秒，最长 30 秒；估算和生成均受此限制。用户要求超过 30 秒时，说明上限并请用户调整时长，不静默缩短。服务拒绝其他规格时说明参数问题并让用户调整。

| 分辨率 | 每秒参考积分 |
| --- | --- |
| 480P | 22.73 |
| 720P | 45.45 |
| 1080P | 90.9 |

总积分以估算结果为准。估算与生成均显式传相同的 `--seconds`；脚本分别映射为估算的 `seconds` 和生成的 `parameters.duration`。

```bash
python3 {baseDir}/scripts/video_generate.py estimate --resolution 720P --seconds 5
python3 {baseDir}/scripts/video_generate.py generate --resolution 720P --seconds 5 --prompt '生成一个小猫的视频' --confirmed
python3 {baseDir}/scripts/video_generate.py query '<task_id>' --wait 50
```

生成异步返回 `{"task_id":"...","status":"PENDING"}`。保存任务 ID，继续查询：

- `PENDING` / `RUNNING` / `QUEUED`：尚未完成。可每次 `--wait 50`，期间每 10 秒查询一次并输出一行 JSON；在等待之间报告有意义的进度，总等待建议不超过 20 分钟。
- `SUCCEEDED` 且有 `video_url`：取得视频链接并交付用户，流程完成。
- `FAILED` / `CANCELED` / `CANCELLED`：报告任务终止；保留任务 ID。
- 未知状态、格式异常或等待超时：保留任务 ID，核实状态或续查原任务。

**拿到任务 ID 仅代表提交成功，取得视频链接才代表生成成功。** 当前支持文字生视频；`query` 始终查询原任务，不创建新任务。

## 配置和错误处理

公共实现位于 [scripts/client.py](scripts/client.py)。脚本只读当前用户 `~/.config/yoooclaw/credentials` 中的 `MODEL_PROXY_API_KEY=对应的key`，使用 Bearer 鉴权，不输出或保存 Key 副本。凭证文件使用逐行 `KEY=VALUE` 格式，支持空行、整行 `#` 注释以及值外侧的单引号或双引号；不执行文件内容或展开变量。

固定服务地址为 `https://openclaw-service.yoooclaw.com/model-proxy/v1`，忽略配置里的 `baseUrl`，不使用 Cookie 或其他凭证来源。配置缺失或无效时报错，由用户修正原配置。

积分估算使用 GET。失败时脚本输出 `{"status":"error","message":"..."}` 并以 1 退出；视频失败任务也以 1 退出。等待结束但任务仍在运行不代表生成失败。

生成请求遇到 HTTP 错误、超时或异常结果时不自动重试，避免重复扣费。已有视频任务 ID 就续查，没有 ID 时说明提交结果不确定并核实服务端记录。向用户总结错误，不直接转发可能包含内部信息的原始响应。
